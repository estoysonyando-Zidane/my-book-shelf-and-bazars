# 要件定義書 — my-book-shelf-and-bazars

最終更新: 2026-08-14(フェーズ2要件・描画方式を追記)

## 1. 背景・目的

際限なく増え続ける個人の蔵書を、単なるリストではなく「楽しく」管理できる仕組みを作る。
目的は大きく2つ:

1. **蔵書の一覧・検索性の確保** — 何を持っているか、今どういう状態か(読んだ/読んでいない/貸している)をすぐ把握できること
2. **収集の楽しさ・記録** — 蔵書を眺めること自体に体験価値を持たせ、増え続ける本の存在をリアルに・愛着を持って感じられること

他の並行プロジェクトとは独立して、本プロジェクト固有の要件として定義する。

## 2. 利用者・利用シーン

- 利用者は**自分一人**。ログイン機能は設けない(将来必要になった場合に追加できる設計にはしておく)
- 利用シーンは**自宅での管理がメイン**。外出先(書店・古本市・バザール)での即時確認は必須要件ではない
- 利用デバイスは**PCがメイン**。スマホでもPCと同じ表示・体験ができるようにする(レスポンシブ対応)
- 想定蔵書数: 現在約500冊 → 将来的に数千冊規模まで増える前提で設計する

## 3. 機能要件

### 3.1 本の登録

- **バーコード/ISBNスキャン**によるカメラ経由の自動登録
- **ISBN/書名の手入力検索**による登録
- 書誌情報(タイトル・著者・出版社・出版年・表紙画像など)は外部APIから自動取得する
  - **openBD / 国立国会図書館サーチAPI** と **Google Books API** を併用し、片方でヒットしない場合はもう片方を試す
- API取得情報に加えて、**実測サイズ(縦横高さ等)は手動入力**できるようにする(背表紙の太さ表現などビジュアルに利用)
- **登録時の重複チェック**: 同じISBNが既に登録されていれば知らせる。複数所持は削除・別登録ではなく「所持数」フィールドで管理する
- タグ/ジャンルは**ISBN登録時にAPI情報から自動設定**しつつ、**自由入力欄も別途用意**し、後から追加・編集できる

### 3.2 蔵書ステータス管理

- 読書ステータス: **未読 / 読書中 / 読了** の3段階
- **貸出管理**を含む:
  - 貸出先(名前)、貸出日、返却予定日を記録
  - 返却予定日を過ぎている場合は「超過」と分かるように表示する
  - 貸出中の本は仮想本棚から消える(住人が持ち去った場合と同様の扱い)
- 感想・レビューは**自由記述のコメント形式**で、新しい順に並ぶ(コメント欄のような形式)。貸出先の人が書き込むことも想定する

### 3.3 検索・フィルタ・並び替え

- 登録される書誌情報の項目(タイトル・著者・ジャンル/タグ・出版年・読書ステータス・貸出中かどうか・積読年数・購入日 等)について、**考えられるものは一通り検索・フィルタ・並び替えできるようにする**

### 3.4 仮想本棚ビュー(蔵書のメイン表現)

- 蔵書一覧は**背表紙が並ぶ本棚**として表現する(表紙の面出し一覧ではなく、通常の本棚のように背表紙を並べる形)
  - 背表紙画像は基本的に取得できないため、**タイトル・著者名を用いて自動生成**する
  - 本の厚みはページ数・実測サイズなどから推定して表現する
  - 表紙画像自体は、本をタップ/クリックした詳細表示で使用する
- 棚の並び替え・グルーピング軸: ジャンル別・著者別・購入日順・読了日順・積読の古さ順・色順・実測サイズ・出版年など、登録される書誌情報を軸として利用できるようにする
- 物理的な本棚の配置(現実の置き場所)とは**連動させない**。仮想本棚上の並びのみを扱う
- 表紙・背表紙画像は外部APIのURLをそのまま参照する方式とする(自前でのダウンロード保存はしない)

### 3.5 積読の可視化

- 登録日を起点とした「積読タイマー」を持ち、**どれくらいの期間読まれていないか(積読の古さ)**を可視化する

### 3.6 「住人」— 蔵書空間に住む正体不明の存在(本プロジェクトの中核機能)

蔵書空間には、ユーザーが直接操作・干渉できない**自律行動する存在**が1体(まずは1体固定)いる。役割は、増え続けて忘れられていく蔵書に対して「あ、こんな本あったな」「次はこれを読もうかな」という気づき・示唆を与えること。

- **行動**: 本の周りをうろつく、その場で本を読む、昼寝する、気に入った本を自分の部屋に持ち込む、など。動きは画面を見ている間にわかる程度〜のんびりした速度で、不自然な瞬間移動はしない
- **不完全さ・人間くささ**: 持ち込んだ本を**返し忘れる**、住人自身が**積読してしまう**こともある。意図的に予測不能・非効率な挙動を許容する
- **本の状態との連動**:
  - 住人がその場(棚)で読んでいる本 → タップすると書誌情報が見られる
  - 住人が部屋に持ち込んだ本 → 棚からは消える。ユーザーは「部屋への入り口」を見つける必要がある(探索要素)。部屋の中で読んでいる住人をタップ、または部屋の棚に並んでいる持ち込み済みの本をタップすると書誌情報が見られる
  - 住人が持っている間、その本は**貸出不可**(ユーザーも一時的に読めない/貸せない扱い)。ただし**予約**は可能とする
- **正体・見た目**: 名前を持たない、**正体不明の「気配」レベルの存在**であることが核。既存キャラクター(クラバウターマン、なまけたろう、脂肪ちゃんなど)は雰囲気の参考であって、そのものを模倣しない。ユーザーからは意図が読めない
- **示唆の届け方**: 通知や強調演出はしない。静かな存在感として、眺めていて気づく程度にとどめる(積極的な通知UIは作らない)
- **スコープ**: MVPでは「部屋への入り口探索」は含めず、まずは棚から本が消える/戻るという基本挙動のみを実装する。入り口探索は近い将来の追加フェーズで着手する

### 3.7 ビジュアルの雰囲気・描画方式

- 全体は**どこか薄暗く神秘的だが、遊び心のある本棚**。ただし本自体(背表紙・タイトル)の視認性は落とさない
- 住人も同様に神秘的でありながら、**愛嬌・可愛らしさ**があり、干渉できないのに愛でたくなる・見守りたくなるような存在として表現する
- 視点は**平面(横スクロールの棚)**。3D空間をカメラが動き回るような表現は採用しない
- 「のっぺりした絵」にならないよう、**質感(物質性)を持たせた2D表現**を採用する
  - ランタイムはCanvas/SVGベースの2D描画のまま(3Dエンジンは常時稼働させない)
  - 質感(光の当たり方・影・素材感)は、事前にBlender等で作成・レンダリングした**ライティング/質感素材(焼き込み画像)**を、本ごとの色・タイトルと合成して表現する(=素材作成のみ3DCGツールを使い、アプリの実行時は軽量な2D描画に留める方式)

## 4. データモデル(主要項目)

| 項目 | 取得方法 | 備考 |
|---|---|---|
| タイトル / 著者 / 出版社 / 出版年 / ISBN | API自動取得 | openBD/NDL, Google Books |
| 表紙画像URL | API自動取得 | ダウンロード保存はしない |
| ページ数 | API自動取得(可能な範囲) | 背表紙の厚み推定に使用 |
| 実測サイズ | 手動入力 | 背表紙表現に使用 |
| ジャンル/タグ | API自動設定 + 自由入力 | 複数付与可 |
| 所持数 | 手動入力 | 重複登録時の管理に使用 |
| 読書ステータス | 手動更新 | 未読/読書中/読了 |
| 積読開始日 | 登録日を起点に自動計算 | 積読タイマー表示用 |
| 貸出情報 | 手動入力 | 貸出先、貸出日、返却予定日、超過フラグ |
| 住人保有状態 | システム管理 | 棚上 / 住人が読書中 / 住人の部屋 / 予約中 |
| 感想・コメント | 自由入力(複数、時系列) | 投稿者(自分 or 借りた人)を記録 |

## 5. 非機能要件

- **認証**: オーナー(自分)はログイン不要。ただしフェーズ2(8章)で同僚向けの招待制アクセスを追加する
- **スケール**: 現状500冊、将来数千冊規模までを想定した設計とする
- **デバイス**: PCメイン、スマホでも同等の表示・体験ができるようにレスポンシブ対応する
- **画像**: 外部API参照方式(自前ストレージは持たない)
- **エクスポート/バックアップ**: 必須要件ではない(将来検討)

## 6. 技術スタック(提案)

- フロントエンド: React + Next.js。本棚・住人の描画はCanvas/SVGベースの2D描画(可視範囲のみ描画する仮想化を行い、数千冊規模でも軽快に動作させる)
- 質感素材の作成: Blender等の3DCGツールで質感(光・影・素材感)をあらかじめレンダリングし、画像素材として2D描画に合成する(ランタイムは3Dエンジンを使わない)
- バックエンド/DB: Node.js API + PostgreSQL(Renderでの運用を想定)
- 「住人」の状態はサーバー側で一元管理し、PC/スマホどちらからアクセスしても同じ状態が見えるようにする(経過時間から状態を導出する軽量な方式)
- 外部API: openBD / 国立国会図書館サーチ、Google Books API(フォールバック併用)

## 7. スコープ外・将来検討事項

- 住人の「部屋への入り口」探索要素(近い将来の追加フェーズで着手)
- 統計グラフ(冊数推移、ジャンル内訳など)
- 住人を複数体にする、または性格を変える等の拡張
- データのエクスポート/外部バックアップ
- 外出先での利用を前提としたオフライン対応・PWA化

## 8. フェーズ2: 同僚向け閲覧・貸し出し共有機能

自分の蔵書管理(フェーズ1)が動いた後に着手する、**招待制**の共有機能。目的は同僚への貸し出しをアプリ上で回せるようにすること。

- **アクセス方式**: 招待制。不特定多数に公開するリンクではなく、招待された同僚のみがアクセスできる
- **同僚に見せるもの**: 仮想本棚ビュー、書誌情報、住人、予約機能、感想・コメント(閲覧・投稿とも可)
- **同僚に見せない/操作させないもの**: 本の登録・編集・削除、貸出管理(オーナー側の管理画面)。住人はそもそも誰も操作できない
- **同僚の識別**: 個人情報は取得しない。初回アクセス時に**名前を設定する簡易プロフィール**を作成させ、以降ブレないように同じ名前が使われるようにする(パスワード等の本格的な会員登録は不要)
- **コメント投稿**: 同僚も名前+本文で感想・コメントを投稿できる(オーナーと同じコメント欄を共有)
- **予約**: 同僚は本を予約できる。住人が持っている本にも予約は可能
- **予約管理画面**: オーナー側に、誰が何を予約しているか一覧できる管理画面を用意する。プッシュ通知等のリアルタイム通知は不要(オーナーが能動的に確認する運用)
